# 蒼釉の回廊 / Azure Cloister — レンダリング引き継ぎ

設計・事前検証済み。本番の全尺レンダリングは未実行。次の担当はリポジトリのルートで以下を実行する。

```bash
bash tools/render-azure-cloister.sh
```

GPUアクセスが制限される環境では、このコマンドに必要なGPUアクセスの許可を取得する。ソフトウェア描画へ切り替えない。実行後は `output/azure-cloister/production.log` を監視し、終了コード0と末尾の `Completed` を確認する。実行中に別のGPUレンダリングを開始しない。

出力は `output/azure-cloister/azure-cloister.mp4`、PNG原版は `output/azure-cloister/master-frames/`。スクリプトが描画、全PNGのデコード検査、sRGB→BT.709変換、MP4の枚数・尺・色タグ検証まで行う。事前確認だけなら `bash tools/render-azure-cloister.sh --check`。

## 作品と設定

青緑の陶釉をまとった細密彫刻と銅色の大きな曲面。中央の三葉装飾を見つめたまま24度逆方向に周回し、距離0.59→0.77へ引く。近景から周囲の回廊を見せる10秒のワンショット。5次補間で発進・停止を滑らかにする。音声やタイトルは含めない。

- シーン: `scenes/production/azure-cloister.yaml`
- 1920×1080 / 30fps / 300枚 / 32 samples per pixel / f32
- GPU: NVIDIA GeForce RTX 3070、WGPU GL、平均GPU duty 80%
- 画角23度、開口半径0.0012、注視点に合焦
- AO 64 steps、soft shadow 96 steps、反射rayなし
- 表面に固定した青緑・銅のpalette、控えめで幅のあるハイライト
- H.264 / yuv420p / CRF 14 / slow / BT.709 limited range

Alchemyの形状定義は継承し、材質・照明・レンズ・経路を新しく設計した。独立した新形状ではない。96→32 sppは画質との交換であり、96 sppと同一画質とは扱わない。

## 前作の改善点の適用

前作の制作記録 `docs/ivory-vault-production.md` と実測報告 `output/ivory-vault/profiling/report.md` を参照した。

1. GPU負荷制限時も131072画素単位で処理する既存の改善版を使用。小さな分割への回帰を防ぐため、検証したバイナリのSHA-256を固定する。
2. 前作で見た目が変わった形状・色の反復数削減を避け、125/240反復とorbit定義を維持。サンプル数・ショット尺で時間予算を調整する。
3. 少ないサンプルでも強いボケや鋭いハイライトが荒れにくいよう、開口を小さくし、光沢を抑える。時間方向のAAやモーションブラーは未実装のため、緩い移動量と滑らかな加減速を使う。
4. 全300枚の経路検査と低解像度の全尺プレビューを先に実行する。
5. 実行スクリプトで排他ロックを取得し、起動済みrenderer/harnessも検出する。ロックを使わず後から起動する別プロセスまでは防げないため、同時描画を避ける。
6. PNG原版を保持し、明示的なsRGB→BT.709変換を行う。中断後は同じコマンドで有効な既存PNGから再開する。

## 3時間の時間予算

2026-09-20、この環境のRTX 3070 / GL / 80% dutyで、**本番と同じ1080p・32 spp・全効果**を7地点で実測した。CLIの `preview --profile final` を使い、解像度や品質の上書きはしていない。

| フレーム | 秒/枚 |
|---|---:|
| 0 | 19.140 |
| 50 | 17.504 |
| 100 | 17.977 |
| 150 | 19.124 |
| 200 | 20.546 |
| 250 | 21.998 |
| 299 | 22.193 |

平均19.783秒×300枚 = **約99分**。全枚を最遅地点で計算すると約111分。

設計上の保守予算は `22.193秒 × 300枚 × 1.5 + 600秒 = 10,586.85秒`、**約176分27秒**。50%の負荷変動余裕と、PNG保存・QC・動画化用の10分を含む。これは7地点からの推定であり、全フレームや他GPU・他負荷での完了時間を保証する測定ではない。

起動スクリプトは描画開始からQC・動画化を含む処理に合計3時間の上限を設ける。上限に達したら停止し、PNGを残す。時間内完了を偽装するための自動画質変更やフレーム省略は行わない。

## 検証資料

すべて `output/azure-cloister/development/` 以下。

- `composition-sheet.jpg`: 始点・1/4・中間・3/4・終点の構図一覧。画像を目視確認済み。
- `final-proof/frame_*.png`: 本番画質7枚。中間フレームの細密形状・合焦・色分離を目視確認済み。
- `timing.json`: 上記実測と見積式。
- `route-inspection.json`: 全300位置でvalid、最小clearance ratio **0.00780124**、下限0.0001。全視線の遮蔽や連続時間の安全性の証明ではない。
- `motion-frames/`、`motion-proof.mp4`、`motion-qc.json`: 480×270・4 sppの全300枚。経路と効果設定は本番と同じ。低解像度の検査では本番画質の時間方向のちらつきまで保証できない。
- `sample-reference/`: 中央部の96 spp比較用画像。

動画の実時間再生による鑑賞評価は行っていない。数値QCと抽出画像の確認を実施した。本番の全尺QCは起動スクリプトが完了時に出力する。

## 再開と変更禁止事項

`scenes/production/azure-cloister.sha256` でシーン、検証済み実行バイナリ、描画・QC・動画化スクリプトを照合する。通常の引き継ぎで再ビルド、seed・spp・尺・解像度の変更、checksumの更新は不要。照合が失敗したら設定を変えて続行せず、差分を確認する。

失敗・中断時は `production.log` の原因を確認して、同じコマンドを再実行する。GPU異常時に同じジョブを重ねて起動しない。再開により累積実行時間が3時間を超える場合はある。既に完成MP4が存在する場合は上書きせず停止する。完成確認情報は `master-qc.json` と `video-probe.json` に残る。
